# Research Agent Rules

This repository exists to test one representation claim. Work directly on the mathematical object, code, experiment, or manuscript section that can change that claim.

## Scientific priority

1. Correct observation operator, split, target and metric.
2. Code must implement the stated equations.
3. One experiment must distinguish a named competing explanation.
4. Negative and null results change the method or stop the claim.
5. Documentation remains short and points to one authority.

## Prohibited patterns

- Do not add hash, checksum, digest, receipt, ledger, or repository-integrity systems.
- Do not use broad exception handling or silent scientific fallback.
- Do not add factory, manager, registry, adapter, or wrapper layers for hypothetical future use.
- Do not create duplicate plan, status, theory, or manuscript documents.
- Do not describe synthetic or analytic tests as real PHM evidence.
- Do not stack diffusion and flow as unexplained modules. Their roles are fixed by observable subspaces.

## Change rule

One PR should change one scientific decision. A completed scientific slice contains:

```text
implementation or frozen protocol
+ actual result
+ interpretation boundary
+ corresponding manuscript update
```

For code, run the nearest semantic test. Run the full suite once before PR merge.
